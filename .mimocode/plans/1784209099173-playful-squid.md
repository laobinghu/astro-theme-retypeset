# 博客原创验证系统集成计划

## Context

为 astro-theme-retypeset 项目集成博客原创验证技术，将 OpenTimestamps（OTS）时间戳 + SSH 数字签名组合方案嵌入构建流程，实现零信任、可公开审计的原创证明。项目当前使用 pnpm，无 GitHub Actions 工作流，站点 URL 为 `https://eaverse.top`。

---

## 实现步骤

### Step 1: 创建 SSH 签名密钥生成脚本

**文件**: `scripts/generate-signing-key.sh`（新建）

- 生成 ed25519 签名专用密钥对 `~/.ssh/blog_signing_key`
- 仅用于签名，不用于登录，职责分离
- 脚本仅供一次性手动执行，不纳入自动构建

### Step 2: 创建 OTS + 签名自动化脚本

**文件**: `scripts/verify-originality.sh`（新建）

核心流程（在 `dist/` 目录上操作）：
1. 遍历 `dist/**/*.html`
2. 对每个 HTML 文件用 SSH 私钥签名 → 生成 `.sig` 文件
3. 对每个 `.sig` 文件用 OTS 打时间戳 → 生成 `.sig.ots` 文件
4. 生成 `allowed_signers` 文件供读者验证
5. 输出验证指南

**依赖处理**:
- SSH 签名：系统自带（macOS/Linux），CI 中通过 secret 注入私钥
- OTS：通过 `pip install opentimestamps-client` 安装

### Step 3: 创建公钥分发目录

**目录**: `public/.well-known/`（新建）

- 将公钥 `blog_signing_key.pub` 放置在 `public/.well-known/signing-key.pub`
- 创建 `public/.well-known/allowed_signers` 模板（或由脚本动态生成）
- 创建 `public/verification.md` 验证说明页面（可选，放在 about 页面链接即可）

### Step 4: 更新 package.json 脚本

**文件**: `package.json`（修改）

添加新脚本：
```json
{
  "scripts": {
    "sign": "bash scripts/verify-originality.sh",
    "build:verified": "pnpm build && pnpm sign"
  }
}
```

### Step 5: 创建 GitHub Actions 工作流

**文件**: `.github/workflows/deploy.yml`（新建）

流程：
1. Checkout 代码
2. 安装 pnpm + Node.js
3. 安装 Python + opentimestamps-client
4. 运行 `pnpm build`
5. 从 secrets 恢复 SSH 私钥到临时路径
6. 运行签名 + OTS 时间戳脚本
7. 部署（适配用户实际部署方式，如 Cloudflare Pages / Vercel / 自建）

**所需 GitHub Secrets**:
- `BLOG_SIGNING_PRIVATE_KEY`: SSH 私钥内容（base64 编码）
- `BLOG_SIGNING_PUBLIC_KEY`: SSH 公钥内容
- 部署相关 secret（根据实际部署平台）

### Step 6: 创建验证说明页面

**文件**: `src/pages/verification.astro`（新建）

简洁的验证指南页面，包含：
- 什么是原创验证
- 如何验证（OTS 时间戳 + SSH 签名两步）
- 下载公钥链接
- 验证命令示例

## 验证方式

1. **本地测试**: 手动运行 `bash scripts/verify-originality.sh`，检查 `dist/` 下是否生成 `.sig` 和 `.sig.ots` 文件
2. **密钥验证**: 使用生成的公钥 + `ssh-keygen -Y verify` 命令验证签名
3. **OTS 验证**: `ots verify *.sig.ots` 确认时间戳有效
4. **CI 验证**: 推送代码后检查 GitHub Actions 运行日志
